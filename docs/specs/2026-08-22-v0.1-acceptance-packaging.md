# v0.1 Acceptance Packaging

Status: accepted
Date: 2026-08-22

This specification defines what "v0.1 is usable by its operator" means as a
black-box contract over the compiled `andrew-agent` binary.
It adds no product feature.
Every requirement below is either an observable of the existing binary or a
document that states an already-implemented boundary honestly.

## Scope

In scope:

- A deterministic acceptance layer that spawns the compiled CLI in a
  machine-like temporary environment and a real temporary Git repository.
- An opt-in live smoke path that exercises the real installed Codex.
- An operator-facing `README.md` rewrite.
- A written v0.1 limitations contract.
- A release checkpoint that verifies packaging metadata without publishing.

Out of scope, and rejected if a change requires one of them:

- Any new command, flag, capability, or runtime behavior.
- Any hand edit under `src/generated/codex-app-server/**` or
  `schemas/codex-app-server/**`.
- Publishing the package, creating a tag, or creating a GitHub release.
- Streaming Git inventory, submodule support, stale-lock auto-recovery,
  Oracle or shared-memory wiring, GUI, and multi-agent orchestration.

## Acceptance environment

The deterministic layer must construct its whole world and must never inherit
the operator's real environment.
Each acceptance run creates:

- A temporary `HOME` that no real dotfile reaches.
- A temporary source root, initialized as a Git repository, holding a
  committed `agent-bundle.toml` and its referenced files, left clean.
  `ANDREW_AGENT_CODEX_SOURCE` points at it.
- A temporary state root under a separate parent, so the runtime path overlap
  check has a real separation to verify.
  `ANDREW_AGENT_STATE_ROOT` points at it.
- A synthesized `auth.json` written into the managed `codex-home` at mode
  `0600`, containing only non-secret fixture values.
  Real authentication material is never read, copied, hashed, or printed.
- A fake `codex` executable in a temporary directory, with
  `ANDREW_AGENT_CODEX_BIN` pointing at its canonical path.
  It must answer `--version` with exactly `codex-cli 0.148.0` followed by a
  newline on stdout and nothing on stderr, because `classifyCodexVersion`
  compares the full stdout string and requires empty stderr.
  Its `app-server` subcommand speaks the pinned JSONL protocol from a
  scripted fixture.
- A temporary target repository, initialized as a clean Git repository with at
  least one committed tracked file.

The acceptance path spawns `process.execPath` with `dist/cli.js` and asserts
on the child's stdout, stderr, and exit code.
It must not import command handlers; that surface is already covered by
`test/integration/cli.test.mjs`.

## Scenarios

Each scenario names its observable and its expected exit code.

1. **Build and invoke.**
   After `pnpm build`, the compiled entry point answers `--help` with the four
   public command usages and exits 0.
   An unknown command exits 2.
1. **Doctor readiness.**
   On a fresh state root `doctor` reports `ACTIVE_INSTALL` as a blocker and
   exits 1, while the source, manifest, and Codex version findings are already
   `ready`.
   After a run has installed a candidate, `doctor` reports no blocker and
   exits 0.
   Removing the manifest turns `MANIFEST_VALID` into a blocker, which proves
   the check reads what it claims to read.
1. **Bundle build and install.**
   The first `run` builds a content-addressed artifact under the state root's
   `bundles/`, installs it into `codex-home`, and records
   `active-install.json`.
   Repeating the build from the same clean source yields the same
   `bundleDigest`.
1. **Contained edit.**
   A `run` whose scripted turn writes one file leaves exactly that file
   modified in the target repository, and leaves the source root and the rest
   of the state root byte-identical.
   Terminal status `completed`, exit 0.
1. **Declined boundary action.**
   `answerApproval` refuses to prompt at all unless stdin is a terminal, so a
   gated action reaching a piped stdin is answered `decline` without any
   operator interaction.
   This is the default in every non-interactive context, including CI, and is
   documented as a v0.1 boundary rather than treated as a defect.
1. **Approved boundary action.**
   The approve path is therefore reachable only over a pty.
   The acceptance layer drives it with `expect`, which macOS ships, selects
   the accept choice, and asserts that an `accept` decision reached the App
   Server.
   The two scenarios differ in outcome, which is what distinguishes a real
   decision from a default.
1. **Final output.**
   The final record prints starting HEAD, terminal HEAD, turn ID, terminal
   status, and final Git status, each bounded and escaped.
1. **New-process continuity.**
   A second process invoking `status <thread-id>` and `resume <thread-id>` on
   the same thread and repository reads the persisted record written by the
   first process.
   `status` with no argument resolves the latest thread for the current
   repository.
   Exit 0.
1. **Interrupted install.**
   A state root carrying a leftover install journal invalidates the active
   installation: `doctor` reports `ACTIVE_INSTALL` as a blocker and the next
   `run` refuses with exit 3, leaving the managed home and the source tree
   exactly as it found them.
   The successful rollback path is owned by
   `test/integration/install.test.mjs`; the acceptance layer asserts the
   fail-closed behavior an operator actually observes.
1. **Cleanup.**
   After every scenario, no `codex` child process survives, `run.lock` is
   released, and no scratch directory remains under the temporary parent.

## Exit codes

The acceptance layer asserts the mapping already implemented across
`src/cli.ts`, `src/commands/run.ts`, `src/commands/resume.ts`, and
`src/commands/status.ts`: 0 success, 1 failure, 2 usage, 3 preflight or
runtime preparation, 4 App Server, 130 interrupt.
A scenario that expects a nonzero code asserts the exact code, never merely
"nonzero".

## Generated-contract verification policy

`test/contract/client.test.mjs` currently invokes bare `codex` from `PATH` and
requires exactly `codex-cli 0.148.0`.
That makes `pnpm check` depend on which Codex happens to be installed; on the
development machine it fails today against `codex-cli 0.149.0`.

The test must instead read an explicit pinned-binary environment variable:

- Variable set and its `--version` matches the pin: run the byte-for-byte
  inventory comparison, unchanged.
- Variable set and its version does not match: fail.
  A wrong pin must never be reported as success or as a skip.
- Variable unset: skip, and print one line naming the variable and saying the
  generated-tree verification did not run.
  A silent skip is rejected, because a layer that quietly contributes no
  coverage is indistinguishable from a layer that passed.

The pin stays at the version declared in `src/constants.ts`.
Raising it would require regenerating both trees, which is a contract change
and out of scope here.

## Live smoke

A separate opt-in path, guarded by `ANDREW_AGENT_REAL_SMOKE=1` and pointed at
a binary by `ANDREW_AGENT_SMOKE_CODEX_BIN`, checks the one property the
fixture App Server cannot: that the portable configuration this product
installs is one the real Codex accepts.
It installs a candidate through the deterministic path, then runs the real
`app-server --strict-config` probe against the managed home and requires exit 0.
It refuses any binary that is not the pinned version, and it refuses the
operator's production managed home.

It stops at configuration acceptance.
Driving a real turn additionally requires real credentials, which this smoke
deliberately does not supply, so the real-turn gate is reported as
`[UNVERIFIED]` rather than satisfied with production authentication.

The smoke earns its place: the doctor fixture profile sets
`analytics_enabled`, which the real `codex-cli 0.148.0` rejects as an unknown
configuration field.
Nothing in the deterministic layer can see that, because a fixture accepts
whatever it is given.

## Documented v0.1 limitations

`README.md` states these as product boundaries, not as defects to hide:

- macOS only; the runtime refuses any other platform.
- The target repository must be a clean Git worktree.
- Submodules and gitlinks are unsupported and rejected.
- The bundle source root must be a clean Git worktree root, and every bundled
  file must be Git-tracked.
  Measured on the development machine on 2026-08-22, the default source root
  `~/.codex` carried 100 dirty entries, almost entirely Codex's own writes
  under `memories/`, so an operator using the default path will be blocked and
  should point `ANDREW_AGENT_CODEX_SOURCE` at a dedicated clean tree.
- Git command output is bounded at 16 MiB per captured stream.
- App Server JSONL protocol lines are bounded at 16 MiB of UTF-8 wire bytes.
- A stale publication lock is not auto-recovered.
- The Codex version is pinned exactly; a different installed version is a
  Doctor blocker and fails before the App Server starts.
- Capability gating for `oracle` and `shared-memory` exists in the renderer
  but is unreachable from the CLI, which always requests no capabilities.
- Approvals are never granted without a terminal. Any gated action in a
  non-interactive context is declined without prompting.

## Release checkpoint

The checkpoint verifies, without publishing: version `0.1.0` in
`package.json`, `private: true`, the `andrew-agent` bin mapping, an executable
`dist/cli.js` with its shebang, the install instructions in `README.md`, and
the committed lockfile.
No tag, no registry publication, no GitHub release.
