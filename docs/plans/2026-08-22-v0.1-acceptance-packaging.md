# Plan: v0.1 Acceptance Packaging

Date: 2026-08-22
Specification: `docs/specs/2026-08-22-v0.1-acceptance-packaging.md`
Branch: `chore/v0.1-acceptance-packaging`

Each step names the change and the command that decides whether it worked.
No step introduces a product feature.

## 1. Restore a deterministic aggregate gate

Change `test/contract/client.test.mjs` so the regeneration case reads the
pinned binary from an explicit environment variable instead of bare `codex`,
with the three-way policy from the specification: run on a matching pin, fail
on a mismatched pin, skip with a printed notice when the variable is unset.

- Verify, unset: `pnpm test:contract` passes and prints the skip notice.
- Verify, matching pin: point `ANDREW_AGENT_PINNED_CODEX_BIN` at the
  `0.148.0-aarch64-apple-darwin` release binary under
  `~/.codex/packages/standalone/releases/`, then run `pnpm test:contract`;
  the byte-for-byte comparison runs and passes.
- Verify, mismatched pin: the same variable pointed at the 0.149.0 release
  fails, and the failure names the version.

## 2. Build the deterministic App Server fixture

Add `test/fixtures/fake-app-server.mjs`: an executable that answers
`--version` with the pinned string on stdout and nothing on stderr, and whose
`app-server` subcommand replays a scripted JSONL conversation covering a
thread start, item lifecycle, one approval request, and a terminal turn.
The scripted conversation is selected by an environment variable so one
fixture serves every scenario.

- Verify: a focused Node script drives the fixture directly and asserts the
  emitted frames, before any CLI test depends on it.

## 3. Stand up the acceptance harness with one scenario

Add `test/e2e/acceptance.test.mjs` with the environment builder from the
specification and the Doctor readiness scenario only.
The harness spawns `process.execPath` with `dist/cli.js`.

The harness spawns with an explicitly constructed `env`, never a copy of
`process.env`.
`resolveRuntimePaths` reads `HOME`, the three `ANDREW_AGENT_*` runtime
variables, and `PATH` from the child's environment, so an inherited
environment would resolve the operator's real `~/.codex` and real Application
Support directory.
Build that guard first: the harness must refuse to run when `HOME` or either
root resolves outside the fixture root, and the refusal must be observed once
before any scenario assertion is written on top of it.

- Verify: `pnpm test:e2e` passes with the ready case at exit 0 and the
  removed-`auth.json` case at exit 1.
- Verify the guard: point the fixture `HOME` at the real home and confirm the
  harness refuses rather than proceeding.
- Verify the harness is not vacuous: delete the fixture `agent-bundle.toml`
  and confirm the Doctor case fails before trusting its pass.

## 4. Widen to the remaining scenarios

Add, in this order, the bundle build and install scenario, the contained edit,
the approved and declined boundary actions, the final output assertions, the
new-process `status` and `resume` continuity, the interrupted-install
recovery, and the cleanup assertions.

- Verify after each: `pnpm test:e2e`.
- Verify cleanup explicitly: assert no surviving child process, a released
  `run.lock`, no residual scratch directory, and an unchanged source root.

## 5. Add the opt-in live smoke path

Add the `ANDREW_AGENT_REAL_SMOKE=1` guarded case, pointed at a binary by
`ANDREW_AGENT_SMOKE_CODEX_BIN`, which refuses the production managed home and
refuses any binary that is not the pinned version.

The smoke checks configuration acceptance, not a real turn: it installs a
candidate through the deterministic path and then runs the real
`app-server --strict-config` probe against the managed home.
Driving a real turn needs real credentials, which this repository has no
dedicated test account for, so that gate stays `[UNVERIFIED]`.

- Verify: unset, the case skips and `pnpm test:e2e` stays green.
- Verify: set at the pinned binary, the probe exits 0.
- Verify the gate is not vacuous: restore a configuration field the real Codex
  rejects and confirm the case fails naming that field.
